# dsh-system-stats

[English](README.md) | 中文

DeepSeek Harness 的实时 CPU、内存与网络读数。在输入框下方、会话统计左侧增加一个胶囊，在两项之间轮换：先是 CPU 与内存，再是网络速率。

## 为什么需要它

聊天页在输入框下方报告的一切都属于会话：轮次、步骤、token、缓存命中、上下文占用。没有任何一项描述这些数字是在哪台机器上产生的。本插件在同一个页面回答这个问题——一轮变慢是 CPU 吃满、内存将尽，还是传输根本没有在动。

读数描述的是 **Host** 进程所在的那台机器。在另一台电脑的浏览器里访问 `dsh web`，看到的是 Host 的数值，而不是浏览器本机的。

## 显示内容

一个胶囊，两项每五秒轮换一次：

| 项 | 胶囊内 | 点击后 |
|---|---|---|
| CPU 与内存 | `5% · 61%`，每个数字各带一个图标 | 下方那一个弹窗 |
| 网络 | `685 B/s · 1.2 KB/s`，每个方向各带一个箭头 | 同一个弹窗 |

点击弹出的是同一个弹窗，两项都是它：先是 CPU 使用率、核心数与采样窗口，再是内存已用、可用与总计，最后是两个速率。点击不会只回答比胶囊更窄的问题——即使在显示速率时点开，CPU 与内存的数字同样在里面。

CPU 与内存合用一项，因为两者都是一句很短的百分比；两个速率较长，需要独占该项。两项都各有两个数字、各带一个图标，读法一致。胶囊里只出现数字——由图标指明是哪一项——完整名称放在无障碍名与弹窗里。

两项共用同一个方框，按两者中较宽的一项定宽。每一项都会在胶囊旁边以脱离文档流、不可见的方式排一遍——脱离文档流所以不会推动整行，不设宽度上限所以量到的是数字真正需要的宽度——胶囊取其中较宽的一次作为自身宽度。这个宽度在页面打开期间只增不减，因此无论是轮换还是流量突然变大，都不会牵动整行。较窄的一项把余量花在自己的间隙上，而不是留在数字之外——留在外面会被行自身的间距放大成下一枚胶囊前一个明显的空洞。数值也不是唯一的读法：把鼠标悬停在胶囊上或让它获得焦点，轮换就停在指针下的那一项；点击则弹出与会话统计胶囊同款的、贴着触发点的弹窗。弹窗打开期间轮换保持不动，因此里面的数字就是点击时那一项的数字；按 Escape 或点击别处即可关闭。

Host 取不到的读数——平台没有计数读取器、路由被拒绝——显示为 `—`，而不是一个数字。胶囊不会把上一次的读数留在屏幕上冒充当前值。

## 数值来源

- **CPU**：两次 `node:os` `cpus()` 读数；占用比例按两者累计 CPU 时间之差计算 `1 - idle / total`。
- **内存**：macOS 读 `vm_stat`，其 free + inactive + speculative 页可被回收，而 `os.freemem()` 会把文件缓存占满的机器报成内存将尽；Linux 读 `/proc/meminfo` 的 `MemAvailable`。其他平台、以及任何一次读取失败，都回退到 `os.freemem()`。
- **网络**：macOS 读 `netstat -ibn`，Linux 读 `/proc/net/dev`，两者都对非回环网卡求和。排除回环，是因为一台与自身通信的机器在 `lo` 上搬运的字节数超过所有物理网卡之和。

## 一次读数的开销

没有任何定时采样。只有当页面主动请求时 Host 才去读机器，且每个 `intervalMs` 最多一次；页面按路由返回的节奏轮询——因此页面关闭时机器开销为零，同时打开两个页面也只共用一次采样。页面隐藏时暂停轮询，重新可见时立即读一次。

安静一段时间后的第一次请求没有足够新的前值可减，因此会重新建立基线并测量一个 250 毫秒的窗口，而不是报告一段「页面关了多久就平均多久」的数值。

## 路由

`GET /system-stats/api/metrics` 返回一份 JSON 读数：`intervalMs`、`at`、`sampledOverMs`、`cpu.percent` 与 `cpu.cores`、`memory.totalBytes` / `usedBytes` / `percent` / `source`，以及 `network.receivedBytesPerSecond` / `sentBytesPerSecond`（平台没有读取器时为 null）。

该路由先经过 `connection` 服务的 `requestRejection`——DSH 自带的 Host、Origin、Fetch-Metadata 校验以及浏览器登录令牌认证——然后要求 `x-dsh-system-stats: 1` 请求头，与 [`dsh-usage-stats`](../dsh-usage-stats/README.zh.md) 一致。缺少 `connection` 服务即拒绝，绝不放行。

## 配置

| 键 | 取值 | 默认 | 含义 |
|---|---|---|---|
| `intervalMs` | 500–60000 | 3000 | 两次采样之间的最短间隔，也是页面轮询的节奏 |

超出范围的值会让挂载直接失败，而不是被夹到边界：一个要求了不可用节奏的组合会被报出来，而不是被悄悄纠正。

profile 的 `cordis.patch.yml` 可以覆盖该行的 config；覆盖时必须重述每一个键，因为按 id 定向的覆盖会替换整行。

胶囊自身的轮换节奏是显示常量，不是采样选择：无论胶囊是否轮换过，读数都按 Host 的节奏刷新。

## 开发

```sh
node --test "plugins/dsh-system-stats/tests/*.test.mjs"
```

`tests/metrics.test.mjs` 用记录下来的计数报告固定解析器与差值运算；`tests/host.test.mjs` 固定路由的信任栅栏、配置校验，以及「一个间隔内只采样一次」的约定；`tests/client.test.mjs` 在 jsdom 中对着桩路由渲染这个胶囊，覆盖轮换、悬停保持、单一测量方框与两个弹窗。

## 已知限制与后续工作

- 这里没有 Windows 的网络读取器，因此该平台网络项不可用；内存回退到 `os.freemem()`。
- 读数是整台机器的，没有按进程拆分，也没有磁盘、温度或 GPU 计数。
- 网络数值对全部非回环网卡求和，因此 VPN 隧道的字节会与承载它的物理网卡一并计入。
- 方框宽度取两项中较宽的一次测量值，因此出现比既往更长的速率时它会变宽；高度固定，整行的基线不会移动。
